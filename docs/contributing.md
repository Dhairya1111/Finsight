# Contributor Notes

## Priorities

When contributing to FinSight, prioritize:
1. correctness over feature count
2. clear source attribution
3. explicit demo-vs-live labeling
4. reusable analytics functions
5. honest disclaimers and limitations

## Backend expectations

- add type hints
- keep route handlers thin
- place calculations in analytics/services
- prefer provider abstractions over vendor lock-in
- add or update tests for behaviour changes

## Frontend expectations

- include loading, error, and empty states
- keep cards/charts reusable
- prefer accessible labels and semantic HTML
- avoid making pages look empty in demo mode

## Documentation expectations

- explain methodology, not just implementation
- document data sources and assumptions
- avoid claims that imply personal financial advice
